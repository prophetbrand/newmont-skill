# Full suite, 2026-11-17: 14 cases × 3 runs

Each case ran three times as independent Opus subagents. Each was given only the path to SKILL.md and the case prompt, ran unattended, and was told "write questions.md and stop" if the process called for a question. Opus graders scored every run against the case graders, reading the run's reply, output files, run record and log. `check_deck.py` was re-run on every deck. Branch `feat/template-routing-oct2025-guidelines`; the work was split into batches A (5 cases), B (5 cases) and C (4 cases).

## Defects

Quotes are as given in the batch reports.

- **D1. The logo ask blocks Word and HTML builds** (word-memo 3/3, html-one-pager 3/3, off-palette run-3). SKILL.md:171: "For Word, HTML or email, ask the person for the approved artwork (Corporate Communications supplies it); if they say to proceed without it, use the logo image embedded in the template master…". SKILL.md:98 stops unattended runs on any missing must-have: "any other must-have that is missing means you write the questions down … and stop". SKILL.md:96 says the template decides the logo and "Asking about these wastes the person's time". The logo is not in the must-have table, but line 171's imperative is read as a gate. Fix direction: make it decide-and-state (use the template-master logo and say so).
- **D2. A user-supplied bracketed value triggers a question** (word-memo 3/3). All 3 runs asked about "From: [Your name]" although SKILL.md:98 says to "build with placeholders". Nothing says a bracket the user wrote is an intended placeholder and not a missing must-have. Deck runs handled "[Q1 2027]" correctly, so the gap is non-deck formats and intake.
- **D3. Verbatim and casing rules are implicit or conflict, and the checker cannot catch it** (qbr 04 run-1, fix-off-brand 01 runs 1 and 2). The only explicit "word for word" rule is SKILL.md:247 (restyle section). SKILL.md:160 "keep their words" covers only overflow. SKILL.md:226 makes `--required-text brief.txt` optional and agent-authored, so the builder can lower-case its own reference text. SKILL.md:157 "Titles are one-sentence statements in sentence case" conflicts with "Keep all the content" and with line 162 "keep their words … as they are". `check_deck.py:27` normalises with `.lower()`, so recased text still passes.
- **D4. The router misses this financial wording and the skill tells runs to follow it** (financial 02, 03, 06, 08, 0/3). `scripts/route_template.py` DETAILED_CUES has "financial performance", "financial results" and "quarterly results" but not "financials", "financial" or "reporting"; with "quartlery" misspelt nothing matches and `--unattended` returns `executive_summary (defaulted)`. SKILL.md:66: "Its rules, which you follow rather than re-derive:". SKILL.md:69 routes Detailed View for "operational or financial performance and results". SKILL.md:72: "If no one can answer (an unattended run ...), it defaults to Executive Summary". Nothing says "executive summary slide" names a slide's purpose and not the template; all 3 runs cited the user's wording as support.
- **D5. SKILL.md:120 allows four-column risk layouts** (long-content 03 run-1). The line reads "| Headed comparison (before/after, option A/B, risks/mitigations) | `Two/Three/Four Column Comparison` | header one line; body ~320 characters per column |". `references/layouts-executive-summary.md:43` gives Four Column bodies "~175 chars" and line 112 maps "Risks and mitigations" to `Two Column Comparison`. Either the skill line or the grader must change.
- **D6. No rule on placeholder format or repeating metrics across slides** (financial 05 runs 1 and 2). The only guidance is SKILL.md:85: "bracketed placeholders like `[TRIFR 0.0]`".
- **D7. The render step leaves artefacts** (complete-brief 11 run-3). SKILL.md:227 gives `soffice --headless --convert-to pdf --outdir out deck.pptx` and says nothing about where a LibreOffice profile may live or what must be gone at delivery. Also left: financial run-3 `render/lo-profile`, just-go run-3 `render/old.pdf`, just-go run-2 `render/requests.superseded-first-build.jsonl`.
- **D8. Every `save()` writes a log line, so a rebuild logs one request twice** (complete-brief run-1, long-content run-2, fix-off-brand runs 1 and 2, photo run-1). SKILL.md:236: "The kit writes the log line on `save()`." Replies had to explain the duplicates.
- **D9. Log fields for asked-and-stopped runs are inconsistent** (html-one-pager). In runs 1 and 3 `clarifying_question_asked` is false although the run stopped to ask, and run-1 set `output` to a file that was never built. Run-2 wrote true and null.
- **D10. No rule for a requested off-palette colour** (off-palette 01, 02, 03 run-3). SKILL.md:56 covers "Say so in one line if the person asks why a colour differs" and line 234 covers one-line departures in the reply. Nothing says a colour the person explicitly asks for is built as asked and stated as a departure; run-3 treated it as a question.
- **D11. No rule on weekday/date mismatches** (off-palette). The "never invent … dates" must-have pushed run-3 to ask; run-1 flagged and built; run-2 said nothing. 14 February 2027 is a Sunday.
- **D12. Wrong role map for `Quarterly Performance`** (fix-off-brand, first build wrong in all 3 runs). `tests/fixtures/roles-detailed_view.json:30`: `"lead": 1 … "head3": 16` maps the first column header to `lead` and the takeaway bar to `head3`. Cause: `scripts/newmont_deck.py:92`, `lead = [i for i in rest if i["type"] == "BODY" and i.get("size") == 14 and 110 <= i["top"] <= 130]`. Filling head1..head3 puts metric 3 in the takeaway bar.
- **D13. `Thank you Opt 5` with one photo is unspecified** (photo-backdrop variance, no FAIL). SKILL.md's layout table says "`Thank you Opt 1` (`Opt 5` with own photos)". The layout has 2 picture slots; 2 runs used a "PHOTO: replace" box and 1 dropped the slot.
- **D14. The timeline table has no fixed shape** (photo-backdrop variance, no FAIL). SKILL.md: "A process, timeline or framework | `Title Sub and Content` with a timeline table", with no column or row convention; 3 runs produced 3 table shapes.
- **D15. Relative `NEWMONT_BRAND_SOURCES` resolves against the skill root** (missing-source, informational; the case accepts it). `brand_sources.py` line 37 `pick("NEWMONT_BRAND_SOURCES", …)` plus root-relative resolution. Runs 1 and 2 got an error pointing at `/Users/bpatel/dev/newmont-skill/empty-sources`, which does not exist; run-3 passed an absolute path. The smoke run reported the same behaviour for `NEWMONT_BRAND_LOG`.

Fixes: D1 logo is decide-and-state with `brand_sources.py --logo`; D2 user-written brackets are intended placeholders; D3 verbatim rule applies everywhere and the checker's required-text compare is case-sensitive; D4 router cues for financials/reporting/quarterly plus a rule to apply the Phase 3 lists when nothing matched; D5 risks pair in `Two Column Comparison` with the reference limits; D6 placeholders show their format and metrics appear once; D7 `save(render=True)` renders into `render/` with an isolated LibreOffice profile and a clean-up rule; D8 a rebuild replaces its log line; D9 stop-to-ask log fields spelled out; D10 requested off-system colours are built and stated; D11 date inconsistencies are flagged, not asked; D12 `lead` needs ≥ 600 pt width and `takeaway` is its own role (role snapshots regenerated); D13 `Thank you Opt 5` only with two photo files; D14 timeline tables have fixed columns; D15 env paths resolve against the working directory.

After the rerun: the memo and off-palette graders 04 were updated to the October 2025 document spec and to accept white text on a requested band; the skill now names guideline sections by number, fixes the financial table's periods and change column, asks for invented rows to be listed as suggestions, and counts only the person's requests as departures; the run record's `defaulted` flag is false when the run overrides the router. Not rerun after these last edits.
