# Agent Builder mini run, 17 November 2026

A first live test of the Skill zip in Microsoft 365 Copilot's Agent Builder, driven on Prophet's tenant through the Copilot app inside Microsoft Teams (macOS) with the mac-screen-use skill. The agent was configured and tested in Preview only; Create was not clicked, so nothing is published in the tenant.

## What was done

1. Agents > New agent > Skip, Configure tab.
2. Name `Newmont Brand Agent`, description from `agent-config.md` (440/1,000 chars), instructions from `agent-instructions.md` (7,814/8,000 chars).
3. Skills > Add > Upload skill: `dist/newmont-brand-copilot-skill.zip` (21.9 MB). Accepted; listed as `newmont-brand` with the SKILL.md description.
4. Preview tab, one prompt: a three-slide tailings strategy deck for site leaders with the pillar text supplied, asking for the .pptx, the template and layouts used, and whether python-pptx was available.

## Result

- The sandbox showed "Coding and executing" three times and replied in about two minutes.
- **python-pptx was available** in the Skills sandbox. The agent ran the kit, not a hand-rolled builder.
- Template: Executive Summary, reason "matched strategy/explainer cues", no clarifying question. Layouts: `1_Cover slide Opt 1`, `Three Column Panels`, `Thank you Opt 1`.
- Sources named with versions: Brand Guidelines October 2025 (SHA 5d4380f98f04), Executive Summary Feb 2026 (SHA 80564d1019e2); Detailed View reported as not in the package.
- The agent reported running the skill's checker and a render, and printed the LOG line in the skill's format.
- Output saved to OneDrive at `Documents/Copilot/Created/newmont-tailings-strategy.pptx` (11.3 MB) with a download link in the reply.

## Triple export, 15:27: cause and fix (packaged, not yet retested)

The three `newmont-q3-2026-qbr` copies differ in their slide XML, so they are three separate saves, not one file exported three times: the agent built, ran the checker, adjusted and saved again inside one turn. The sandbox confirmed its working directory is `/mnt/data` and that the workspace is ephemeral per turn; Copilot exports what is written there after each code run, so every re-save becomes `<deck> 2.pptx`, `<deck> 3.pptx`.

Fix in `package_for_copilot.py`: the sandbox note gains a "One save per deck" paragraph (iterate in `/tmp/newmont-work/`, copy the final deck, build script and run record into the working directory once), and the kit example's `d.save` path points at that scratch folder. To make room, the Reply format section now lives in the moved references file, since the Agent Builder Instructions already define the reply shape. SKILL.md is 19,106 characters for the full package and 19,288 for the detailed_view-only variant. 77 tests pass. The swap onto the draft agent and the recount of OneDrive copies are still to do.

So the rebuild-and-resave loop is gone; the remaining duplicate is the same deck written twice, which points at the final copy into the working directory being exported once as it lands and again at the end of the run, or at a save followed by a copy of the same bytes. The reply itself is now tight: template and reason, both sources with editions, the link, the OneDrive path, the five layouts, the LOG line.

The agent cannot reconstruct its own write calls after the turn (the workspace is gone), so the second copy's cause has to be read from the files: identical bytes except the core.xml modified timestamp means the same deck was saved twice, seconds apart, not rebuilt. The likely sequence is a `d.save` into the working directory and then a second save or copy of the same object, for example when the reply's "run record" step re-saves. Next step for the kit: make `Deck.save` idempotent for an unchanged deck (skip the write when the slide XML is unchanged) or have the packaged example save once to scratch and `shutil.copy` once; then recount. Two copies per build is acceptable for the pilot and the deck is valid either way.
